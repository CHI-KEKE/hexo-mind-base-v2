<h2>十個字元，怎麼檢查有沒有打錯？</h2>
<p>台灣身分證字號把分類資訊、個人編號與輸入錯誤檢查，放進短短十個字元。最後一碼由前面的內容算出來，讓程式可以檢查一部分輸入錯誤。</p>
<div class="bc-bears" aria-hidden="true"><div class="bc-bear"><span class="bc-face"></span></div><div class="bc-bear small"><span class="bc-face"></span></div></div>
</div>
<h3>先把一組號碼拆開</h3>
<p>以 <code>A123456789</code> 說明各位置的角色：</p>
<div class="bc-id-parts">
<div class="bc-id-part"><strong>A</strong><span>地區代碼</span></div>
<div class="bc-id-part"><strong>1</strong><span>性別碼</span></div>
<div class="bc-id-part"><strong>2345678</strong><span>七位編號</span></div>
<div class="bc-id-part"><strong>9</strong><span>檢查碼</span></div>
</div>
<div class="bc-table-scroll" tabindex="0" role="region" aria-label="位置與內容與用途"><table class="bc-table"><thead><tr><th>位置</th><th>內容</th><th>用途</th></tr></thead><tbody><tr><td>第 1 碼</td><td>一個英文字母</td><td>地區分類代碼；計算時須依對照表轉換。</td></tr><tr><td>第 2 碼</td><td>性別碼</td><td>本文國民身分證驗證範例接受 <code>1</code> 或 <code>2</code>。</td></tr><tr><td>第 3 至 9 碼</td><td>七位編號</td><td>在固定地區與性別前綴下，提供區分個人的編號空間。</td></tr><tr><td>第 10 碼</td><td>檢查碼</td><td>由前九個字元推算，不是額外自由選擇的編號。</td></tr></tbody></table></div>
<div class="bc-note">
<h3>檢查碼通過，代表什麼？</h3>
<p>代表輸入符合這套格式與加權規則，不代表已查證號碼確實核發，也不代表輸入者就是本人。<code>A123456789</code> 曾出現在真實冒用案例中，本篇只用於閱讀與計算說明。</p>

<div class="bear-chalk">
<h2>七位編號，可以容納多少組合？</h2>
<p>固定「同一個地區代碼＋同一個性別碼」後，主要編號空間來自中間七位數。最後的檢查碼是算出來的，不能再替容量多乘一次十。</p>
<div class="bc-code">
<div class="bc-code-bar">固定前綴下的編號結構</div>
<pre class="bc-pre" data-lang="text">A 1 2345678 9
│ │ │       │
│ │ │       └─ 檢查碼：算出來的，不能自由選
│ │ └───────── 7 位流水編號
│ └─────────── 性別碼
└───────────── 地區代碼</pre>
</div>
<div class="bc-board">
<h3>七個位置，每個位置十種數字</h3>
<div class="bc-equation">10⁷ = 10,000,000</div>
<p>若七位編號的每一種組合都可使用，單一固定前綴最多有 1,000 萬種組合。這是格式的理論上限，實際可配賦數量還要看發號規則與保留限制。</p>
</div>
<div class="bc-note">
<h3>編號空間不等於當下人口</h3>
<p>原稿從「一個縣市住進 1,000 萬人」想像容量壓力。對發號制度而言，更直接的問題是固定前綴下累計占用了多少編號，不能只看目前住在當地的人數。</p>
<p>若同一前綴累計所需編號真的超過可用空間，就會面臨 <code>namespace</code> 耗盡，需要調整發號規則或制度設計。這裡是在分析容量限制，沒有斷言目前已耗盡，也沒有假設主管機關會採用哪種擴充方式。</p>
</div>

<h2>A123456789，曾經是真實的困擾</h2>
<p>依 2020 年 7 月 10 日鏡週刊報導，住在新北市泰山區、當時 63 歲的謝條根先生，因字號 <code>A123456789</code> 長期遭冒用，約 20 年間反覆需要向警局與地檢署說明。新北市民政局因此成立專案協助變更字號。</p>
<p>資料來源：<a href="https://www.mirrormedia.mg/story/20200710edi024">鏡週刊：身分證 A123456789 真有其人（2020-07-10）</a>。</p>
<div class="bc-note brown">
<h3>容易記住的號碼，也可能被反覆拿來使用</h3>
<p>檢查碼能檢查數字規則，卻無法防止別人填入一組已知且符合規則的字號。這個案例說明了「號碼格式正確」與「確定是本人」之間的差別。</p>
</div>
<details>
<summary>展開案例細節與當時的處理方式</summary>
<ul>
<li>報導形容這是一組「一條龍」字號，遭冒用上百次，涉及詐騙集團申辦信用卡、公司逃漏稅及網路援交等情境。</li>
<li>冒用事件差點引發家庭衝突，也損害信用，甚至無法申辦手機門號。</li>
<li>約 20 年間，他經常往返全台警局與地檢署。依報導描述，後來部分承辦人員已認得這位「職業受害人」，不再反覆傳喚。</li>
<li>報導所稱的「5 年前」是相對於 2020 年。在鐵路局訂票黃牛案中，他曾於 1 週內收到 3 張偽造文書傳票。</li>
<li>他曾請鐵路局取消該字號的訂票權利，需要搭車時再自行購票，以減少雙方困擾；報導指出這也減少了許多冒用案件。</li>

<div class="bear-chalk">
<h2>權重，讓位置也參與計算</h2>
<p>只把數字相加，會消掉位置資訊。把 <code>1234</code> 的 2、3 交換成 <code>1324</code>，總和仍然相同。</p>
<div class="bc-table-scroll" tabindex="0" role="region" aria-label="輸入與沒有權重的計算與結果"><table class="bc-table"><thead><tr><th>輸入</th><th>沒有權重的計算</th><th>結果</th></tr></thead><tbody><tr><td>1234</td><td>1 + 2 + 3 + 4</td><td>10</td></tr><tr><td>1324</td><td>1 + 3 + 2 + 4</td><td>10</td></tr></tbody></table></div>
<p>權重是在每個位置貼上不同的數學標籤。即使使用相同數字，位置改變時，加權結果也有機會改變。</p>
<h3>把交換前後的差異寫出來</h3>
<div class="bc-table-scroll" tabindex="0" role="region" aria-label="情況與第一個位置：權重 x與第二個位置：權重 y與貢獻"><table class="bc-table"><thead><tr><th>情況</th><th>第一個位置：權重 x</th><th>第二個位置：權重 y</th><th>貢獻</th></tr></thead><tbody><tr><td>原本</td><td>數字 a</td><td>數字 b</td><td>ax + by</td></tr><tr><td>交換後</td><td>數字 b</td><td>數字 a</td><td>bx + ay</td></tr></tbody></table></div>
<div class="bc-board">
<h3>差異 = 數字差 × 權重差</h3>
<div class="bc-equation">(ax + by) − (bx + ay)</div>
<div class="bc-equation">= ax − bx + by − ay</div>
<div class="bc-equation">= (a − b)(x − y)</div>
<p>兩個不同數字若放在不同權重的位置，交換後的加權總和就可能改變。這是利用權重偵測交換錯誤的數學核心。</p>
</div>
<div class="bc-note">
<h3>總和改變，不一定能被 mod 10 抓到</h3>
<p>最後比對的是除以十的餘數。只有差異不是十的倍數，餘數才會改變；差異為零或十的倍數時，檢查碼仍可能通過。</p>
<p>例如本規則最後兩位的權重同為 1，交換這兩位時，<code>x − y = 0</code>，加權總和完全不變。這些例外說明檢查碼是有限的偵錯工具。</p>
</div>
</div>

<div class="bear-chalk">
<h2>mod 10，把總和收斂成十種餘數</h2>
<p>最後一碼只有一個十進位數字，因此只能保存 0～9 這十種狀態。<code>mod 10</code> 把加權總和轉成這十種餘數之一，再選一個檢查碼，把完整總和補成十的倍數。</p>
<ol class="bc-steps">
<li><h3>先算不含檢查碼的加權總和</h3><p>以 <code>A123456789</code> 為例，字母 A 對應 10。拆成 1、0 後，與後面的數字分別乘上權重；此步先不加入最後的 9。</p><div class="bc-equation">S = 1×1 + 0×9 + 1×8 + 2×7</div><div class="bc-equation">＋ 3×6 + 4×5 + 5×4 + 6×3 + 7×2 + 8×1 = 121</div></li>
<li><h3>用餘數求出檢查碼</h3><div class="bc-equation">c = (10 − (S mod 10)) mod 10</div><div class="bc-equation">c = (10 − 1) mod 10 = 9</div><p>外層再取一次餘數，是為了讓原本已可整除的情況得到 0，而不是得到無法放進一位數的 10。</p></li>
<li><h3>帶回完整號碼重新驗證</h3><div class="bc-equation">121 + 9 = 130</div><div class="bc-equation">130 mod 10 = 0</div><p>完整加權總和可以被十整除，因此通過檢查碼驗證。</p></li>
</ol>
<div class="bc-note">
<h3>不同內容可能落在同一種餘數</h3>
<p>大量不同輸入只對應十種餘數，因此重新計算只能偵測部分改動。它不是加密，也不能證明資料從未被修改。</p>
</div>

<p><code>string</code> 可以透過索引取得 <code>char</code>。本題的十個字元都位於 ASCII 範圍，索引從 0 到 9。</p>

<h3>數字字元：用編碼差距取得數值</h3>
<p>為了做乘法、加法與取餘數，需要把數字字元轉成整數。<code>Char Offset</code> 利用字元編碼的相對位置；只要某段字元連續排列，就能用相減取得相對位置。</p>

<h3>C# 完整範例</h3>
<p>保留原稿的查表、陣列與迴圈寫法。範例使用 C# 9 以上語法；放入專案時需有 <code>System.Collections.Generic</code> 命名空間，<code>string?</code> 對應可為 null 的參考型別註記。</p>
<details>
<summary>展開 C# 完整範例</summary>
<div class="bc-code">
<div class="bc-code-bar">C# · IsValidTaiwanId</div>
<pre class="bc-pre" data-lang="csharp">static bool IsValidTaiwanId(string? id)
{
    // 1. 基本檢查
    if (string.IsNullOrEmpty(id) || id.Length != 10)
    {
        return false;
    }
    // 2. 統一轉成大寫
    id = id.ToUpperInvariant();
    // 3. 英文字母對應的地區代碼
    Dictionary&lt;char, int&gt; letterCodes = new()
    {
        ['A'] = 10,
        ['B'] = 11,
        ['C'] = 12,
        ['D'] = 13,
        ['E'] = 14,
        ['F'] = 15,
        ['G'] = 16,
        ['H'] = 17,
        ['I'] = 34,
        ['J'] = 18,
        ['K'] = 19,
        ['L'] = 20,
        ['M'] = 21,
        ['N'] = 22,
        ['O'] = 35,
        ['P'] = 23,
        ['Q'] = 24,
        ['R'] = 25,
        ['S'] = 26,
        ['T'] = 27,
        ['U'] = 28,
        ['V'] = 29,
        ['W'] = 32,
        ['X'] = 30,
        ['Y'] = 31,
        ['Z'] = 33
    };
    // 4. 第一碼必須是合法英文字母
    char letter = id[0];
    if (!letterCodes.TryGetValue(letter, out int letterCode))
    {
        return false;
    }
    // 5. 第二碼只能是 1 或 2
    if (id[1] != '1' &amp;&amp; id[1] != '2')
    {
        return false;
    }
    // 6. 後面 9 碼必須全部是數字
    int[] numbers = new int[9];
    for (int i = 1; i &lt; id.Length; i++)
    {
        if (id[i] &lt; '0' || id[i] &gt; '9')
        {
            return false;
        }
        numbers[i - 1] = id[i] - '0';
    }
    // 7. 把地區碼拆成兩位數
    int firstDigit = letterCode / 10;
    int secondDigit = letterCode % 10;
    // 8. 身分證各數字的權重
    int[] weights =
    {
        8, 7, 6, 5, 4, 3, 2, 1, 1
    };
    // 9. 計算 checksum
    int sum = 0;
    sum += firstDigit * 1;
    sum += secondDigit * 9;
    for (int i = 0; i &lt; numbers.Length; i++)
    {
        sum += numbers[i] * weights[i];
    }
    // 10. 可以被 10 整除就通過
    return sum % 10 == 0;
}</pre>
