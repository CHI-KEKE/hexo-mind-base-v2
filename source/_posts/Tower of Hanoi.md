## 🍲 今天想做的事

有三根柱子（A、B、C），以及 N 個大小不同的圓盤，開始時都堆在 A 上（小的在上，大的在下）。每次只能移動一個圓盤，且不能把大的放在小的上面。要怎麼把整堆圓盤從 A 搬到 C？

## 🍲 徒手劈柴

### 如果有 1 個...

👉 需要 **1 次移動**

<br>

### 如果有 2 個...

- 先把上面那個搬開（一次）
- 搬最底下那個（一次）
- 再把上面那個放回去（一次）

👉 總共 **3 次**

<br>

### 如果有 3 本書...

- 先搬 2 個（會用 3 次）
- 搬最底下一個（1 次）
- 再搬 2 個回去（3 次）

👉 總共是 **3 + 1 + 3 = 7 次**

## 🍲 問題的結構

我們想搬 n 個盤子時，可以分成三個步驟

- 先把上面 n-1 個盤子搬到「中間柱子」(暫存)。
- 再搬動最大的第 n 個盤子到目標柱子。
- 最後再把那 n-1 個盤子搬回目標柱子上。

這三步裡，第一步 和 第三步 都是一樣的動作：「搬 n-1 個盤子」
也就是說，這兩步都會再呼叫自己，由此不斷的循環下去~~，直到宇宙塌縮為止~~

<br>
<br>

## 🍲 思考背後的意涵

河內塔代表的是一種「結構化的問題拆解」

1️⃣ 先把上面 N−1 個盤子移到 B（暫存）
2️⃣ 把最大那個盤子移到 C
3️⃣ 再把 N−1 個盤子從 B 移到 C

💡 這三步，第二步是「直接動作」，但第一步和第三步，結構上其實跟原本的問題一模一樣 —— 只是「盤子數量變少」而已。這就是「自相似（Self-similarity）」的特徵 —— 小問題的形狀和大問題完全一樣，只是規模縮小

分支圖
```plaintext
Hanoi(3, A, C, B)
├─ Hanoi(2, A, B, C)
│  ├─ Hanoi(1, A, C, B)
│  ├─ Move(2) Move disk 1 from A to C
│  └─ Hanoi(1, C, B, A)
├─ Move(3)
└─ Hanoi(2, B, C, A)
   ├─ Hanoi(1, B, A, C)
   ├─ Move(2) Move disk 1 from B to C
   └─ Hanoi(1, A, C, B)
```

這個結構就像一棵「任務樹」，每一個節點都代表一次「子問題」的呼叫。

## 🍲 呼叫樹 (Recursion Tree)
 
由以上的分析得知，整個問題大致上是長這樣
```PLAINTEXT
T(n) = 2 * T(n-1) + 1
```
這裡的「2」就是代表兩次遞迴呼叫（左子樹、右子樹），因此這個遞迴形成一棵「二元遞迴樹 (binary recursion tree)」

```PLAINTEXT
            T(3)
        /        \
    T(2)          T(2)
    /   \         /   \
T(1)   T(1)   T(1)   T(1)
```
每個節點 T(k) 都會生出 兩個子節點 T(k-1)。當 k=1 時，就是底層（base case），不再分支，樹的高度是 N（因為每一層代表少一個盤子）。

第 1 層有 1 個節點 (T(n))
第 2 層有 2 個節點 (兩個 T(n-1))
第 3 層有 4 個節點 (四個 T(n-2))
…
第 N 層有 2^(N-1) 個節點 (最底層的 T(1))

所以**節點總數**會是
```PLAINTEXT
1 + 2 + 4 + 8 + … + 2^(N-1)
```

接著計算**等比數列和**
```PLAINTEXT
## 總和
S = 1 + 2 + 4 + 8 + … + 2^(N-1)

## 我們把整個式子乘以 2
2S = 2 + 4 + 8 + … + 2^(N-1) + 2^N

## 然後把上面這兩個式子「相減」
(2S - S) = (2 + 4 + 8 + … + 2^N) - (1 + 2 + 4 + … + 2^(N-1))

## 中間的項目都互相抵消掉，只剩下
S = 2^N - 1
```

每一個節點就代表「一次遞迴呼叫」，而在河內塔問題中，每次遞迴的最後都會有一次移動動作，所以最少移動次數也是 2^N - 1。

## 🍲 類比這個問題

如果換個角度想：我有一個初始狀態 A，要轉換成目標狀態 C。這個轉換太複雜，所以我定義一個「中介行為」F，讓我一步步接近目標。
這種「把大問題拆成小問題」的思維，其實無所不在。例如公司的組織架構：
```PLAINTEXT
公司 (大問題)
 ├─ 部門 (中問題)
 │   ├─ 小組 (小問題)
 │   │   ├─ 個人 (最小單位)
```

整個組織就像一棵「遞迴的任務樹」，每一層都在把上層的任務拆解成更小、更可解決的子任務。CEO 制定公司策略，部門主管以同樣邏輯制定部門目標，小組長再以同樣思維安排團隊工作。這就是河內塔所呈現的哲學：大問題的解法，其實隱藏在小問題的重複之中。

## 🍲 程式碼

```csharp
void Hanoi(int n, string from, string to, string aux)
{
    if (n == 1)
        Console.WriteLine($"Move disk 1 from {from} to {to}");
    else
    {
        Hanoi(n - 1, from, aux, to);
        Console.WriteLine($"Move disk {n} from {from} to {to}");
        Hanoi(n - 1, aux, to, from);
    }
}
```

這段程式表達出「自相似」的邏輯，每次都在解一個規模更小的相同問題，當遞迴層層展開時，我們看到的不是單純的搬運，而是一種把複雜問題變簡單、再重複執行的智慧

## 🍲 結語

河內塔是一種「思考方式」。生活中的許多困難，其實都像一座巨大的河內塔。我們無法一次解決所有事，只能拆開、排序、遞迴地前進，學習、成長、改變都是如此，每一步都像是在搬一個盤子，看似微小，但方向正確；當我們回頭看時，才會發現自己，早已完成了一場龐大的遞迴
